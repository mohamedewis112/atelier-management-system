# نطاق نظام إدارة الأتيليه

## الأقسام الأساسية

- زفاف
- أطفال
- رجالي
- منتجات بيع

يكون لكل قسم قطع مستقلة ويمكن إضافة تصنيفات فرعية لاحقًا.

## تكويد القطع

كل قطعة تأجير يكون لها كود فريد لا يتكرر، مع اسم القطعة وتصنيفها ومقاسها ولونها وصورها وسعرها الافتراضي وحالتها الحالية.

مثال:

- الاسم: سمر سواريه
- الكود: SW-0048
- القسم: زفاف / سواريه
- السعر الافتراضي: 1000 جنيه
- الحالة: متاح

## الحجز ومنع التعارض

عند حجز قطعة في يوم معين يتم حجز فترة حماية تلقائيًا تشمل:

- اليوم السابق للحجز
- يوم الحجز
- اليوم التالي للحجز

مثال: إذا كانت القطعة محجوزة يوم 15، فلا تكون متاحة للحجز أيام 14 و15 و16.

عند تمديد الحجز يعيد النظام فحص المواعيد للتأكد من عدم وجود حجز آخر متعارض.

## الأسعار

لكل قطعة سعر افتراضي يظهر تلقائيًا أثناء إنشاء الحجز، مع إمكانية تعديل سعر الحجز نفسه للمستخدم الذي لديه الصلاحية، دون تغيير السعر الأساسي للقطعة.

## العملاء

ملف العميل يشمل البيانات الأساسية وسجل الحجوزات والمدفوعات والقطع التي تعامل عليها سابقًا.

## المدفوعات

لا يتم تخزين "رقم مدفوع" فقط، بل يتم الاحتفاظ بسجل مستقل لكل حركة مالية، مثل:

- عربون الحجز
- دفعات إضافية
- استكمال المبلغ
- التأمين
- رد التأمين
- خصم جزئي أو كامل من التأمين عند الحاجة

ويظهر دائمًا:

- إجمالي الحجز
- إجمالي المدفوع
- المتبقي

## الصلاحيات

### الأدمن

- إدارة كاملة للنظام
- تكويد وإدارة القطع
- تعديل الأسعار الأساسية
- الاطلاع على جميع العمليات
- الأرباح والخسائر والتقارير
- إدارة المستخدمين والصلاحيات
- مراجعة سجل العمليات

### المشرف

- إنشاء وتعديل الحجوزات ضمن الصلاحيات
- تسجيل التحصيلات
- اختيار السيلز المسؤول
- متابعة التجهيز والتسليم والاستلام
- تقفيل اليومية
- متابعة التشغيل اليومي

### السيلز

- مشاهدة القطع المتاحة والمحجوزة
- البحث والتصفية
- مشاهدة الأسعار
- تنفيذ العمليات المسموح بها
- ربط الحجز بالسيلز المسؤول

### التجهيز

- مشاهدة طلبات التجهيز
- معرفة مسلسل / كود القطعة
- معرفة السيلز المرتبط بالحجز
- تسجيل الموظف المستلم أو المسؤول
- إضافة ملاحظات التجهيز
- تحديث حالة القطعة

## دورة تشغيل القطعة

متاح → محجوز → انتظار تجهيز → جاري التجهيز → جاهز للتسليم → تم التسليم → تم الاستلام → فحص / تنظيف / صيانة → متاح.

كل تغيير حالة يتم تسجيله وتحديثه داخل النظام.

## اليومية

المشرف يستطيع مراجعة وتقفيل اليومية بما يشمل التحصيلات والمبيعات والمصروفات والحجوزات والحركات المنفذة خلال اليوم.

## الأرباح والخسائر

يدعم النظام تسجيل المصروفات إلى جانب الإيرادات للوصول إلى قراءة فعلية للتشغيل، مع إمكانية تطوير تقارير خاصة بالعائد على كل قطعة.

## البحث والفلاتر

يجب أن يستطيع السيلز أو المشرف البحث والتصفية حسب عوامل مثل:

- القسم
- المقاس
- حالة القطعة
- التاريخ المطلوب
- نطاق السعر
- الكود
- اسم القطعة

## التحديث المباشر

عند وجود اتصال، أي تغيير مهم مثل إنشاء حجز أو إنهاء تجهيز يجب أن ينعكس على الشاشات الأخرى دون الحاجة إلى إعادة تحميل يدوي قدر الإمكان.

## التشغيل Offline / Online

الأولوية هي أن يعمل النظام على كمبيوتر الأتيليه حتى في حالة انقطاع الإنترنت.

الهدف النهائي:

- قاعدة بيانات محلية للعمل بدون إنترنت
- مزامنة سحابية عند عودة الاتصال
- سياسة واضحة لمنع تعارض الحجوزات عند وجود أكثر من جهاز
- نسخ احتياطي واستعادة للبيانات

يتم اعتماد تصميم المزامنة النهائي بعد اختبار سيناريوهات الاستخدام الفعلية داخل الأتيليه.
